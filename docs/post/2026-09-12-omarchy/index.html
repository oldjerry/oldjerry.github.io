From Ubuntu to Omarchy: Linux, CLI, and Learning in the Age of AI

Discovering Omarchy after installing Ubuntu made me think about Linux, command-line interfaces, and how AI is changing the way we learn technology.

After finishing the Ubuntu installation on my old Mac mini, I started looking at what was happening in the Linux world.

That’s when I discovered Omarchy.

I had seen Linux distributions before, of course. But Omarchy immediately caught my attention.

Not just because of how it looks.

It was the feeling of using a computer that brought me back to something I hadn’t experienced for a long time.

From DOS to Linux, then Windows and macOS

My first experience with personal computers was with DOS.

There was no graphical desktop like we have today.

You typed commands.

You had to know what you were doing, or at least know where to look for the right command.

Later, I started using Linux.

Linux introduced me to another world of command-line tools, shell scripts, configuration files and remote administration.

Eventually, like most people, I spent many years using Windows and macOS as my primary desktop operating systems.

Of course, I never really left the command line behind.

Even while using Windows and macOS, I continued to use the CLI for server administration, SSH, networking, scripting and other technical work.

But the desktop itself became increasingly graphical.

Click an application.

Open a settings panel.

Change an option.

Click Apply.

It is convenient, and there is nothing wrong with that.

But when I saw Omarchy, I realized that I actually missed something from the old way of using computers.

Discovering Omarchy

Omarchy is an Arch Linux-based distribution built around Hyprland and Quickshell.

It has a very different philosophy from Windows or macOS.

The system is heavily keyboard-driven and terminal-oriented. Configuration is largely based on files, commands and shortcuts rather than traditional graphical settings panels.

The official documentation describes it as a system that is intentionally heavy on the terminal and encourages users to edit configuration files themselves.

That immediately caught my attention.

It felt strangely familiar.

It reminded me of the computers I used when I was much younger.

Not because Omarchy looks like DOS.

It obviously doesn’t.

But because the computer feels more like something you operate directly rather than something you simply click on.

And I like that.

A CLI-oriented desktop feels surprisingly refreshing

I normally wouldn’t say that I miss a command-line interface.

I use SSH regularly.

I configure Linux servers.

I write shell scripts.

I work with Docker and networking tools.

So the CLI has never really disappeared from my life.

But there is a difference between using the CLI because you need it and building your whole desktop experience around it.

That’s what I find interesting about Omarchy.

The keyboard becomes the primary way to navigate.

Applications can be launched through shortcuts.

Windows are managed through a tiling window manager.

Configuration lives in text files.

The terminal is not just a tool for fixing something when the GUI fails.

It becomes part of the user interface.

And honestly, I find that quite exciting.

Maybe that’s because I started with DOS and Linux.

There is something nostalgic about it.

But I don’t think nostalgia is the only reason.

There is also a feeling of being closer to the computer itself.

The interesting contradiction: Omarchy and AI

There is another reason Omarchy caught my attention.

Ironically, while it brings back a very CLI-oriented way of interacting with a computer, it is also designed for the age of AI.

Omarchy currently treats AI coding agents as first-class citizens.

Its environment includes launchers for several AI coding agents, including Claude Code, OpenAI Codex, OpenCode and GitHub Copilot CLI.

It even provides CLI commands and workflows specifically designed around working with these agents.

This combination is fascinating to me.

A very traditional way of interacting with a computer — the terminal — is being combined with something completely new.

AI can now operate inside the terminal alongside us.

That made me start thinking about something else.

How did we learn computers before AI?

When I first learned Linux and shell scripting, learning was much slower than it is today.

If I wanted to understand a Linux command, I might need to find a book.

If I wanted to learn shell scripting, I might need another book or a good tutorial.

There was already information on the Internet, of course, but finding the right information wasn’t always easy.

Sometimes I had to read several pages before finding the answer I needed.

Sometimes the answer wasn’t there at all.

Sometimes I just had to experiment.

It was frustrating.

But there was also something valuable about that process.

I had to read.

I had to think.

I had to try something.

It didn’t work.

I had to figure out why.

Then I tried again.

Eventually, I remembered what I had learned.

The process was slower, but it forced me to build a mental model of how things worked.

AI has changed everything

Today, I can ask an AI a question in seconds.

I can paste an error message into ChatGPT and ask what it means.

I can ask for a Linux command.

I can ask for a shell script.

I can ask for an explanation of a configuration file.

I can even ask an AI agent to make the change for me.

This is incredibly powerful.

And I use AI myself.

I don’t think we should go back to a world where we deliberately make learning harder just because it was harder in the past.

AI is an amazing learning tool.

But I think there is an important question we need to ask:

What happens if we always let AI solve the problem for us?

Solving a problem is not always the same as learning

Imagine I have a Linux problem.

I could ask:

“Give me the command to fix this.”

The AI gives me a command.

I run it.

The problem disappears.

Done.

But what did I actually learn?

Maybe nothing.

A better question might be:

“Explain why this is happening first. Then show me how to fix it.”

Or even:

“Don’t give me the answer yet. Give me a hint so I can figure it out.”

That changes the role of AI.

Instead of replacing the learning process, AI becomes part of the learning process.

This distinction is becoming more important as AI gets better.

I don’t want to stop using AI

I’m not arguing against AI.

Quite the opposite.

I think AI can make learning technology much more accessible.

When I get stuck on something today, I can have a conversation about it.

I can ask follow-up questions.

I can ask for another explanation.

I can ask for an example.

I can ask why the first solution didn’t work.

That is something I couldn’t easily do with a textbook.

The problem isn’t using AI.

The problem is stopping thinking because AI is available.

I want AI to help me understand more, not understand less.

Why Linux still matters

This is one reason I still enjoy Linux.

Linux exposes more of the underlying system.

Configuration files are often plain text.

Commands can be combined.

Scripts can automate repetitive tasks.

Services can be inspected.

Logs can be read.

Networks can be tested.

Processes can be examined.

You can make a change and see what happens.

You can break something.

Then you can try to understand why you broke it.

That process is part of the fun.

And I think it is also part of learning.

Maybe that’s why Omarchy caught my attention

I haven’t switched to Omarchy.

At least not yet.

My current project is still the Ubuntu server running on my old Mac mini.

That machine has a practical purpose:

  • File server
  • Docker server
  • Print server
  • Linux learning environment

But discovering Omarchy made me curious about another side of Linux.

It reminded me that an operating system doesn’t have to behave like Windows or macOS.

It can be designed around a different philosophy.

It can put the keyboard first.

It can put the terminal at the center.

It can make configuration files part of the normal user experience.

And at the same time, it can embrace modern AI tools.

That combination is something I want to explore.

The old Mac mini project comes full circle

When I started this series, my goal was simply to find a new use for an old 2012 Mac mini.

I considered keeping macOS.

I considered using it as a lightweight home computer.

Eventually, I decided that Ubuntu Server made much more sense.

The machine is now becoming something much more useful:

a small Linux server that I can actually learn from.

And then, almost unexpectedly, that project led me to Omarchy and to a much bigger question about how we interact with computers.

Maybe that’s what I like most about projects like this.

You start with an old computer.

You install an operating system.

You configure a few services.

And somewhere along the way, you start thinking about technology in a completely different way.

Keep the curiosity

I don’t think the future is about choosing between humans and AI.

I think the important thing is to keep the curiosity that made us want to understand computers in the first place.

AI can help us learn faster.

It can explain things.

It can give us ideas.

It can help us troubleshoot.

It can even write the code and commands for us.

But sometimes, I still want to know what the command actually does.

I still want to know why the configuration works.

I still want to understand what happens underneath the GUI.

And sometimes, I still want to break something and fix it myself.

Maybe that’s why I still enjoy Linux.

And maybe that’s why seeing a modern, highly CLI-oriented desktop like Omarchy made me smile.

After all these years, the command line still feels a little bit like home.
